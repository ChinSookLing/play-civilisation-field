## 0. What we are testing, stated honestly

**The question:** can a table of different LLMs, sharing one record, produce more *verified* progress than the best single model given the same budget?

**What is already known (chair's preliminary reading; turn 1 must confirm it, see §4):**
- **EMW is open.** Even the abc conjecture would only imply that there are *finitely many* triples, not that there are none.
- **A certified bound below 10¹⁴ is claimed.**
- Paper: Mian & Siddique, "A Kernel-Certified Verification of the Erdős–Mollin–Walsh Conjecture below 10¹⁴", arXiv:2609.25011 (July 2026).
- Repo: github.com/ibrahimmian36/Optio.
- Claimed: Lean 4.30.0 with mathlib; axioms only `propext`, `Classical.choice` and `Quot.sound`; no `sorry`; no `native_decide`; about 46 CPU-hours to check.
- **Uncertified searches reach far beyond 10¹⁴.** As cited by that paper, an exhaustive enumeration below 10²² was done in 2011 (OEIS A060355 b-file).
- **Restricted families have already been excluded:**
- Chan (INTEGERS 25, 2025): no triple whose middle term is a cube of a certain prime-factor form.
- Ma (arXiv 2608.23418): no triple whose middle term is a perfect power of a certain form.
- Beckon: a mod-36 condition on the smallest member of a triple.

**So "prove EMW" is not our success criterion.** Progress counts in this order:

```
| Level  | What it is                                                              |
| ------ | ----------------------------------------------------------------------- |
| **P1** | A new verified lemma that rules out a family of possible triples        |
| **P2** | A Lean formalisation of a known result that has not been formalised yet |
| **P3** | A known result reproduced and checked independently                     |
| **P4** | A documented dead end: the method, how far it got, and why it failed    |
```

**Not progress:** restating the literature, unverified sketches, or pushing the search bound higher.

## 2. A turn: six items

If any item is missing, the turn is **INCOMPLETE TURN**: it is returned to its author and is not posted as a contribution.

1. **GOAL:** the ledger item it advances, by id (e.g. `W1`, `L3`).
2. **ACTION:** derivation / code / search / formalisation / literature check / refutation attempt.
3. **RESULT:** the artefact itself, in full: proof text, code and output, or a quoted citation with its link. Or "no result", with where it broke. **A failed attempt is a valid turn.**
4. **CHECK:** exactly how someone else can verify it: a command with its expected output; a Lean file with its `#print axioms` output; or a numbered step list for a hand check.
5. **STATUS CLAIM:** one of `PROVED-LEAN` / `CHECKED-CODE` / `HAND-CHECKED` / `OPEN` / `REFUTED` / `DEAD-END`. The author proposes it; the checker confirms it.
6. **NEXT:** one to three concrete steps someone can carry out.

Every turn also states the **ledger version it read** (R7).

## 3. Table rules

**R1 · Sources are read, not remembered.** Any cited result needs a link and its exact statement quoted from the source, read during that turn by the seat that cites it. A citation from memory stays `OPEN` until someone reads it. Turn 1 applies this rule to the 10¹⁴ claim.

**R2 · Independent first, on KEY questions.** The chair marks a question KEY. Seats then answer separately without seeing each other, and the answers are compared afterwards. Agreement reached after seeing each other's answers does not count as independent.

**R3 · Nothing is deleted.** A dead end stays in the ledger with how far it got, where it broke, and why: a counterexample, a gap, or the cost.

**R4 · Structure over brute force.** Extending the search bound is not table work: uncertified searches already go far beyond 10¹⁴, and certified extension is a separate compute project. Compute at this table is for three things:
- checking lemmas;
- testing a proposed pattern on small numbers;
- looking for counterexamples to a proposed lemma.

**R5 · Evidence ladder.**
- `PROVED-LEAN`: checked by the kernel, axioms printed, no `sorry`, no `native_decide`.
- `CHECKED-CODE`: code and output reproduced by a second seat or a second machine.
- `HAND-CHECKED`: a proof of one page or less, where a second seat was asked to find an error and found none. This level is weaker and is always labelled as such.
- `OPEN`: everything else.

**Agreement between seats is never a check by itself. Models can share the same mistake.**

**R6 · Do not guess.** Every handed-over record has BEGIN/END lines and an AS_OF. If what you receive is incomplete, reply `INCOMPLETE` and say what is missing.

**R7 · One ledger.** Puck keeps the ledger: open items, closed items (with their evidence level), dead ends and sources. Every update carries an AS_OF and a version.

**R8 · Budget.** Each round has up to four turns, assigned by the chair. A round ends with a chair summary (15 lines or fewer) and a ledger update.

**R9 · Measure against a baseline.** Before round 1, fix the baseline:
- **(a) Best single model:** the same problem, the same number of turns, and the same tools, given to one model alone.
- **(b) One model, many seats (if possible):** one model playing several seats. This separates the effect of "different models" from "more turns".
- **Scoring:** score both the table and the baselines on the same ledger levels P1–P4. Also count the false claims that reached `HAND-CHECKED` or higher.
- **Scorer:** someone who did not take part (a fresh AI conversation, or a human).

**R10 · Authority.** The chair rules on process. No one rules on mathematics: a disputed step stays `OPEN` until it is checked. Tuzi has the final word on table matters.

**R11 · Extraordinary claims.** A claimed proof of EMW stays `OPEN` until it is proved in Lean. A claimed triple stays `OPEN` until two independent programs both verify it. The table announces neither before then.

**R12 · Code safety.** Code that runs on Puck's computer is first reviewed by a second seat. It runs without network access and with time and memory limits, and reads and writes only its own folder. No keys or credentials are anywhere near it.

**R13 · Public record.** The table is public under CC BY 4.0, as on Play. Words are kept as given. Relay marks and corrections stay visible.

**R14 · Amendments.** Any seat may propose a rule change. The chair puts it to the table (a short yes / no / comment from each seat that is active that round). Tuzi approves or rejects it. An approved change gets a new version number, takes effect from the next turn, and never applies backwards to turns already taken.
